## 二、目标岗位 JD 完整文字存档（蜜雪冰城 · AI 应用工程师 15-30K）

- **职位名称**：AI 应用工程师（Agent / RAG 企业知识库）
- **薪资 / 地点 / 要求**：15-30K · 郑州（郑东新区） · 3-5 年 · 本科
- **岗位职责**：
  1. **智能体与业务流开发**：基于 HiAgent 等智能体开发平台，负责企业级业务场景的 AI 应用落地；完成智能体角色设计、Workflow 编排、Prompt 调优与工具集成；结合业务流程构建可复用的智能体与组件库，覆盖知识问答、办公助手、流程自动化、数据分析等典型场景。
  2. **Prompt 工程与效果调优**：负责各类业务场景下的 Prompt 设计与优化；针对不同行业/场景需求调整提示词结构、上下文组织方式与输出格式约束，确保模型输出结果的准确性与可用性。
  3. **知识库建设与管理**：基于平台知识库能力，完成企业知识库的结构设计、文档处理策略配置、内容分块与调优；持续优化检索效果与召回质量，提升问答准确率与知识覆盖率。
  4. **业务需求分析与方案落地**：深入理解各业务部门（**客服、人力、供应链、IT 运维**等）痛点，梳理业务流程与应用场景，提出可落地的智能体/知识库解决方案，推动项目从原型走向生产。
  5. **评测体系与持续迭代**：建立应用效果评测体系（准确率、响应时效、用户满意度等），收集 badcase 并持续迭代优化，保障线上应用稳定运行与效果持续提升。
  6. **插件开发与能力扩展**：根据业务需要开发自定义插件或外部接口集成（Python/API），将工具能力接入智能体，打通企业内部业务系统，实现数据查询与业务闭环。
- **任职要求**：
  - 本科及以上学历，计算机、软件工程、人工智能、数据科学等相关专业优先；
  - 3 年以上开发或算法工程经验，有大模型应用项目从 0 到 1 落地经验；
  - 熟练掌握至少一种主流智能体开发平台（如火山引擎 HiAgent、Dify、Coze、FastGPT 等），具备独立完成智能体与工作流搭建的实战经验；
  - 具备扎实的 Prompt Engineering 能力，能够针对不同业务场景完成高质量提示词设计与调优；
  - 了解 RAG 技术原理，有向量数据库（如 Milvus、Weaviate、Pinecone 等）或 Embedding 模型应用经验者优先；
  - 掌握 Python 开发，能够编写脚本与 API 接口，具备外部系统集成与插件开发能力。
- **加分项**：
  - 有 Workflow 或自动化流程开发经验（如 n8n、Airflow、**LangGraph** 等）；
  - 有企业级知识库或智能客服项目落地经验；
  - 了解 LangChain、LlamaIndex 等 LLM 应用框架；
  - 熟悉零售、餐饮、供应链或数字化办公场景。

### 2. 核心架构概念的“大白话”对照表（复习备忘）

在后续阶段 10～12 的教学中，拒绝堆砌晦涩黑话，统一按以下直观语义理解：

| 专业术语 | 大白话本质 | 在旧版（阶段 1～8）里的痛点 | 在新版（阶段 10～12）与冷链业务里的作用 |
| :--- | :--- | :--- | :--- |
| **流式输出 & 事件流协议（SSE / `AgentEvent`）** | **打字机蹦字 + 外卖进度实时播报小纸条** | 问个复杂问题黑屏卡住 10 秒才一次性吐出答案，像死机一样 | 每隔零点几秒发一张格式统一的小纸条（正在第几步思考、正在打哪个字、正在调哪个工具、耗时多久），终端和网页实时渲染进度 |
| **人工审批检查点（HITL / Checkpoint）** | **遇到危险动作先踩刹车“游戏存档”，等人点同意再读档继续** | 大模型想调什么函数就立刻执行，万一抽风删错数据或乱赔钱根本拦不住 | 遇到标了 `HIGH_RISK` 的工具（如写文件、冷链赔付 > 500 元），立刻暂停不执行，把现场存盘（Checkpoint）；哪怕关机重开，只要人工点“批准”就能读档继续执行 |
| **L1 / L2 / L3 三级分层记忆** | **短期脑子印象（L1）+ 前情提要小本本（L2）+ 永久备忘录（L3）** | `trim(40)` 只留最后 40 句，第 41 句前直接扔掉导致聊久失忆；切在工具调用中间还会导致 API 400 崩溃 | **L1** 按字数（Token）算容量且绝不把“调工具+拿结果”劈成两半；**L2** 把滑出窗口的老对话后台浓缩成 200 字“前情提要”；**L3** 用 BM25 把重要事实跨聊天窗口永久记住 |
| **重试与备用模型降级（Fallback）** | **主模型抽风时自动重试 + 备胎模型无缝顶上** | DeepSeek 接口一旦超时或限流，程序当场报错罢工 | 还没吐字前遇到网络抖动自动等 1s/2s 重试；主模型彻底挂了自动切换到备用模型回答 |
| **死循环护栏（`LoopGuard`）** | **防复读机喝止机制** | 模型有时候钻牛角尖，用一模一样的参数反复调同一个工具直到步数耗尽 | 记住刚调过的“工具名+参数”，发现连续重复调用同一参数时当场发系统提示喝止它 |
| **假大脑离线单测 & 故障注入评测** | **不花钱不连网的 1 秒自动体检 + 故意使坏抗压测试** | 每次改代码都得真连 DeepSeek 手工测，又慢又费钱 | 写一个“按剧本演戏的假模型”1 秒测完所有功能；评测时故意假装工具超时或传错参，检验 Agent 能不能自己改对参数重试 |

### 3. “通用底层框架”与“真实业务 Agent”的关系

$$\text{真正的业务 Agent} = \text{通用底层框架（阶段 1～12）} + \text{业务三件套（公司知识库 RAG + 公司业务工具 + 岗位 SOP 与业务考卷）}$$

- **为什么 12 阶段做完是“企业级单机内核”**：它把流式聚合、记忆防爆、工具并发熔断、高危踩刹车审批、Trace 瀑布图、自动化评测这些**决定 Agent 上线后会不会死机闯祸的底层发动机**全部手写做实了，并用 `Protocol` 预留了替换生产底座的插槽。
- **离大规模多实例生产还差的外围基建**：分布式存储与锁（本地 JSON / 内存锁 → PostgreSQL / Redis）、企业级 RBAC 与容器沙箱、租户限流与成本熔断、真实业务工具（MCP）与知识库（RAG）、多节点工作流编排、容器化监控告警。
- **已完成的阶段 9 与《供应链冷链 Agent》的精准咬合**：
  - `9.4` 的 `ctx: ToolContext` 隐式注入 = 冷链 PDF 第 7-8 页的“注入当前登录 `store_id`，防止门店跨店越权查单”；
  - `9.4` 的 `@registry.tool` + Pydantic 校验 = 冷链 PDF 第 8-9 页的 7 个 OMS/WMS/TMS 业务插件；
  - `9.4` 的 `execute_batch` (`asyncio.gather`) = 冷链 PDF 第 7 页 Node 3“同时并发去 OMS、WMS、TMS 三系统取证”；
  - `9.4` 的 `RiskLevel.HIGH_RISK` + 阶段 11 HITL = 冷链 PDF 第 8、10 页 Node 6“赔付超 500 元亮黄灯踩刹车挂起，等运营点【批准】再打款补发”；
  - `9.5` 的 `Trace → Span` 与瀑布图 = 冷链 PDF 第 11 页“监控单工单各节点耗时与 Token 成本”。

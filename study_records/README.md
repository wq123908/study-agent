## 教练式带写流程

### 开始一节课

1. 读取本页、课程大纲与当前阶段记录，再查看该节涉及的代码。
2. 核对仓库位置、当前分支、未提交修改和 Python 解释器，确认已有代码与记录一致。
3. 用大白话说明本模块在系统中的位置、上游输入与下游用途，必要时用一个简短流程图。
4. 一次只展开一节的一个子步骤。明确本次文件路径、类或函数的职责，再给完整代码。
5. 每轮代码控制在 60 行以内。多参数定义、构造和调用按一个参数一行书写。一个模块较长时，按独立、可验收的子步骤拆开。
6. 给出可直接执行的命令、预期结果和判定条件，等待用户贴出运行结果。
7. 根据实际结果排查或进入下一步。

实现代码由用户录入。AI 在对话中讲解并生成代码，用户明确要求直接修改时再代为编辑。教学代码使用 Python，变量和技术名称保留 English。

### 验收与记录

- 记录本节学习知识点、实际改动文件、运行命令、完整关键输出、遗留问题和掌握情况。
- 新模块先离线验证，有现成模型和存储接口时优先复用 `ScriptedLLM`、内存存储与临时目录。
- 阶段有新增回归需求时补相应测试，并运行现有测试及离线评测。测试数量按实际结果更新。
- 文档中的预期结果与实际输出分别保存。代码和验收有证据后，才把状态改为已完成。
- 用户实际学习时间登记到 [time_log.md](time_log.md)，保留开始、结束和中断记录。
- 每小节通过后核对 Git 差异，按文件路径提交本节代码和进度。提交信息沿用 `study(stage-13.1): 独立运行记录` 这样的格式。
- 实际提交号可在下一次进度更新时补录。每次接续读取最新 Git 状态，避免把文档准备提交当作课程完成提交。

### 现有模块的复用关系

| 现有模块 | V2.0 的接续方式 |
| --- | --- |
| `agent/state.py` | 继续承担既有会话消息、摘要和审批状态。阶段 13 新增独立运行模型，通过不同类型名称表达。 |
| `agent/engine/core.py` | 阶段 13 的契约验收完成后，再逐步接入运行生命周期和新执行策略。 |
| `agent/factory.py` | 沿用组件注入入口，在 Agent 定义和接口阶段接入新能力。 |
| `agent/tools/` | 复用注册、入参校验与执行器，逐步补输出、回执和执行策略。 |
| `agent/memory/` | 复用 L1/L2/L3 与存储，逐步补知识来源、时效和访问范围。 |
| `tests/`、`eval/` | 保存 V1.0 回归基线，并承担 V2.0 的离线验证。 |
| `app/`、`main.py` | 在阶段 18 统一对外接入，原有 CLI、Web 和 HTTP 行为由回归验证。 |
